Launch checklist

Four things break launch day.
Do those first.

Everything else on this page can be fixed after you go live. These four cannot.

Stop — do before any ad runs

Each of these fails silently. Nothing on screen tells you it is broken.

  1. Turn off public sign-up in Clerk

    Right now anyone can create an account and reach the founder dashboard — seller data, deals, and the probate export with deceased people's names.

    Set the instance to invitation only. Also move off the development instance (clerk.accounts.dev) to production.

    Clerk dashboard → your app → Restrictions Breaks: everything

  2. Set FOUNDER_USER_IDS

    The dashboard now checks who you are, not just that you are logged in. Without this variable it falls back to requiring a Clerk organisation — and organisations are off by default, so you would lock yourself out.

    Copy your Clerk user id (starts user_) for both founders, comma separated.

    Clerk → Users → click your user → copy id. Then Vercel → bellwood-app → Settings → Environment Variables Breaks: your own access

  3. Set RESEND_TOKEN and RESEND_FROM

    No email sends today. A seller fills in the form and hears nothing. An agent asks for a login link and never gets one — while the screen says "check your inbox".

    Then verify wearekept.co.uk in Resend (SPF and DKIM) so the mail actually lands.

    Vercel → all three projects → Environment Variables. Then resend.com → Domains Breaks: every lead

  4. Run the database migration

    The rate limiter that stops bots draining your API budget does nothing until its table exists.

    pnpm migrate
    Run from the repo root, once Breaks: cost control

Then merge the work

Two pull requests hold this week's fixes. Merging deploys automatically.

  1. Merge PR #46 — the hardening

    Compliance fixes to emails and the offer PDF, the authorisation guard, rate limiting, and the pricing bugs.

    Set FOUNDER_USER_IDS before this one merges (task 2 above).

  2. Merge PR #45 — the design sweep

    Lower risk. Removes the generic look and the leftover Bellwoods branding.

  3. Check the site loads

    Visit /sell and /agents. Submit one test offer request and confirm the email arrives.

Before you spend money on ads

  1. Point ads at the right pages

    The root / sends everyone to the agents page. Send sellers to /sell and agents to /agents directly.

  2. Add analytics

    There is none. Right now you cannot tell which ads produce leads. Vercel Web Analytics plus one conversion event on the offer form is enough to start.

  3. Add error alerting

    Sentry is switched off. If the offer engine breaks mid-campaign, nothing tells you.

  4. Fill in the legal gaps

    The privacy page needs your company number and ICO registration number. The regulatory page still shows "[pending]".

Your call — nobody else can decide these

Trademark search

KEPT.md says the class 36 search must happen before public use. Paid advertising is public use.

Are PRS, ICO and AML valid under "Kept"?

The site claims all three as Kept. Confirm they hold under the entity actually trading, and pick one membership list — the site says PRS, older emails said NAPB and TPO.

The methodology page percentages

A review flagged the margin table as forbidden. I left it — it is general policy with a made-up example, not a real seller's price, and your position is that the discount is never hidden. Confirm you are happy with it.

Roboto as the body font

It is in the brand kit but it is the Android default, and it flattens every page. Decide with Ant whether to keep it.

Photography

The site is still 100% drawn in code. No real photos anywhere. This is the biggest remaining gap in feeling premium — a founder headshot, a doorway, a real signed letter.

If you only do four things: Clerk sign-up off · FOUNDER_USER_IDS · RESEND_TOKEN · pnpm migrate.

Everything else is recoverable after launch.
